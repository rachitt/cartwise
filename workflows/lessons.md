# Lessons Log

Append-only. One bullet per mistake that cost time: what went wrong, and the rule that prevents it. Read this at the start of every session.

- (seed) Kroger public product API is rate-limited (~10k req/day) — always go through the price cache, never call collectors directly from route handlers.
- 2026-07-03: Codex background tasks failed instantly with "app-server SIGKILL" — the global `@openai/codex` install was corrupt (every invocation exit 137). Fix: `npm install -g @openai/codex@latest`. If a Codex task fails in ~3s, check `codex --version` first before blaming prompts or sandboxing.
- 2026-07-03: Codex's sandbox can only write inside the repo dir and cannot touch `.git` (no branch/commit/push/PR). Workflow: Claude creates worktrees under `.worktrees/` (gitignored, inside the repo), runs npm install, dispatches Codex with "no git commands", then Claude commits/pushes/opens the PR from the worktree.
- 2026-07-03: zsh does not word-split unquoted `$CMD` variables — `CMD="node script.mjs"; $CMD args` fails with "no such file or directory". Use an explicit `node "$PATH"` invocation or a shell function in polling scripts. (Bit again 2026-07-04 in a `for t in $TASKS` poller — quote/iterate explicitly.)
- 2026-07-04: Target RedSky 403 is a **captcha/bot challenge**, not a stale key. The key embedded in target.com IS the hardcoded `9f36…96`; RedSky returns `{"captchaRelativeURL":"/captcha?..."}` to server-originated requests regardless of key or visitor_id. Self-healing key scraping (Slice C) cannot defeat it. Major US grocers (Target, Walmart/PerimeterX, Kroger/Akamai) are all bot-walled — plain server-fetch collectors get challenged. Before speccing a web collector, curl the real endpoint first and check for captcha/challenge responses. Aldi (`api.aldi.us`) does not resolve and ALDI runs e-commerce via Instacart — no clean anonymous price API exists. Real data path = official APIs (Kroger free) or headless-browser/proxy (heavy), not naive scraping.
- 2026-07-04: `npm run dev` inside `apps/api` does NOT load `apps/api/.env`; the app defaults to Postgres on :5432. Only the root `scripts/dev.mjs` injects `DATABASE_URL` into the spawned API env. To run the API standalone against the Docker DB, pass `DATABASE_URL=postgres://postgres@localhost:5433/cartwise` explicitly.
- 2026-07-04: Target RedSky challenge behavior is header-sensitive: the full desktop Chrome UA triggered captcha while the simpler `Mozilla/5.0` UA returned live JSON for stores/search. When a Target request gets 403, log the UA and response body before assuming the endpoint/key is broken.
- 2026-07-04: ALDI US no longer has a useful `api.aldi.us` surface, but the current `www.aldi.us` Instacart Storefront Pro SSR flow creates an anonymous guest token. Use `storefront?zipcode=...` to get `shopId`, `zoneId`, `retailerLocationId`, and the guest token, then persisted GraphQL `Search`, `Items`, and `ItemPricesQuery` for on-demand item/price data. Do not bulk crawl category pages.
- 2026-07-04: Target direct RedSky can be captcha-blocked while Target's own page still renders prices through `cdui-orchestrations.target.com`. For Target, resolve ZIPs with `api.target.com/location_fulfillment_aggregations/v1/preferred_stores`, hydrate stores via `api.target.com/locations/v3/public/{id}`, and fetch product prices from CDUI SLP instead of retrying direct RedSky.
- 2026-07-04: Removing the store picker only from search left cart finalization and product detail reading empty `selectedStoreIds`, and search still capped rendered products. When simplifying a flow, `rg` the old state name and remove every downstream dependency before opening the PR.
